# ADR 0082：多模态重载荷驱逐——旧附件换成描述

- 状态：Accepted
- 日期：2026-09-30
- 关联：[compaction-multimodal-eviction 契约](../architecture/capabilities/compaction-multimodal-eviction.md)；
  [context-compression 活文档](../architecture/context-compression.md)；ADR 0004 / 0017 / 0036 / 0068

## 背景

第三轮对比分析把 A4「多模态重载荷驱逐」列为保留项，条件是「等真实多模态负载」。此后图片输入、工具图片附件、
PDF 文件输入（ADR 0068）相继落地，负载已经存在，而压缩谱系对附件的处理仍有空白：

- `surgical_trim` 只在剪工具文本时顺带丢附件，文本短而图大的工具结果不会被选中；
- `offload` 明确回避带附件的条目；
- **用户消息上的附件没有任何策略处理**——只能等 handoff / sliding 把整段对话摘要或丢弃。

一张图片按保守口径折合 1500 token。带着十几张截图的会话会在文本远未触顶时就被迫整体摘要。

命中 ADR 0017 规则①（内核机制：上下文管理）。

## 决策

1. **新增独立策略 `MultimodalEvictionStrategy`**，不并入 `surgical_trim`。后者按工具名 glob 选择、按文本长度分级，
   与「按附件新旧驱逐」是两套判据；合并会让两边的参数互相干扰。
2. **只看附件、不动文本**。文本是模型当时的观察结论，附件是原始材料；材料可以丢，结论要留。
3. **用描述替换而非静默丢弃**。描述含类型、大小、文件名、sha256 前缀：模型知道那里曾有什么，对话里对
   「那张图」的指称不至于落空；业务可据摘要从自己的存储取回原件。
4. **「最近」按带附件的条目计数**。按附件数计会把一次截图返回的多张图拆开保留一半。
5. **没有可驱逐的附件时不触发**。orchestrator 是 first-wins，本策略优先级高于 `surgical_trim`，
   空转会挡住后者。
6. **默认优先级 25**：高于 `surgical_trim`（更便宜、单次收益更大），低于 `offload`（无损档优先）。
7. **改写只在内存**，与 `surgical_trim` / `offload` 一致：transcript append-only，原件仍在；冷加载后再次驱逐。
8. **进实验层**（ADR 0066），不进稳定层 `__all__`。

## 替代方案

- **降采样 / 重编码图片**：需要图像处理依赖，且各 provider 的计费按尺寸档位而非字节，收益不确定；否决。
- **把附件落盘并留指针**（offload 的做法）：模型经 `file_read` 读回来的是文本，看不到图；无法兑现无损回溯；否决。
- **按附件类型分别配置保留数量**：增加参数面而没有已知需求；否决。

## 后果

- 配置了本策略的会话里，旧附件对模型不再可见；需要模型反复对照的图应由业务重新提供。
- 被驱逐的描述会增加少量文本 token（每个附件约 20 个）。
- R1–R5 见契约。
- 真实 LLM 验证未随本次变更执行，能力矩阵标注待验证。

## 验证

`tests/context/test_multimodal_eviction.py`：协议符合、驱逐与保留、描述内容、payload 形状、不修改入参、
`keep_recent` 按条目计、尾部保护、mid-turn 不动已缓存前缀、越 anchor 需显式放开且如实上报、
小附件保留、同一条目内只驱逐大附件、幂等、触发条件、无候选不触发、orchestrator 让位、空 history、
缺字段附件、取消、参数校验、驱逐后 prompt 不含旧图、token 估算下降。
